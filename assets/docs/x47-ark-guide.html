X47 Ark

Save Windows files, then give the disk to Ubuntu

The USB is the ark. Copy what you want to keep, check the copy, then let Windows go so Ubuntu can own the whole drive.

Start here
  1. Plug in an external USB / HDD (not the dual-boot disk).
  2. Open the app grid → X47 Ark (Utilities folder). A windowed assistant walks you through it.
  3. Follow the steps: Scan → USB → Copy → optional Reclaim.
This can wipe Windows

Reclaim deletes the Windows / MSR / Recovery partitions on the dual-boot disk. It never runs unless verify succeeded, and you must type DELETE WINDOWS. The EFI System Partition and Ubuntu root are never deleted.

What gets copied

Per Windows user, these folders only:

CopiedDocuments, Desktop, Downloads, Pictures, Videos, Music
SkippedAppData, Program Files, the Windows install itself, Default / Public accounts

Layout on the stick: X47-Ark/<timestamp>/Users/<name>/… plus MANIFEST.txt, ARK-README.txt, and a verify report.

Before you start

BitLocker

You do not need to boot Windows. On the Scan step, paste the 48-digit recovery key (Microsoft account → Devices → BitLocker keys, or the paper printout) or your BitLocker password, then Unlock BitLocker. Ark uses dislocker to open the volume read-only and copy your files. That does not permanently turn BitLocker off — you do not need that if you are about to delete Windows. TPM-only protection still needs the recovery key; Ark will not guess or bypass it.

CLI: x47-ark unlock --key-file recovery.txt (runs unlock-verify automatically).

Verify

After unlock, Ark reads user folders and sample files from the volume (UNLOCK_VERIFY=OK). After the USB copy, it checks the manifest, sample checksums, and compares those samples back to the Windows source. Reclaim stays locked unless both checks pass.

Fast Startup / hibernation

Windows often leaves the NTFS volume “dirty.” Boot Windows, disable Fast Startup, then Shut down (not restart / sleep). Ark mounts Windows read-only and aborts if the volume looks hibernated.

External drive only

The backup cannot live on the same disk you are about to wipe. Ark compares device names and refuses a same-disk destination. You need about 1.1× the size of those user folders in free space.

Reclaim — two layouts

Ubuntu can grow in place

Windows sits after Ubuntu. After verify, Ark can delete the Windows partitions and grow the ext4 root from the running system (parted + resize2fs), then refresh GRUB and drop the Windows EFI boot entry.

Ubuntu sits after Windows (typical dual-boot)

A running Ubuntu cannot move its own root partition. Ark writes X47-Ark/finish-ark.sh onto the backup stick. Then:

  1. Shut down the installed system.
  2. Boot any Ubuntu live USB (Try Ubuntu) or the X47 ISO.
  3. Plug in the backup stick.
  4. Run sudo bash /media/ubuntu/*/X47-Ark/finish-ark.sh
  5. Read the plan. Type DELETE WINDOWS.
  6. If the automatic move is skipped, open GParted: move Ubuntu left into the hole, then grow it to fill the disk. Reboot and run sudo update-grub if asked.

CLI

x47-ark — wizard

x47-ark detect — print the layout

x47-ark backup /media/you/USB — copy only

x47-ark verify — check the last backup

x47-ark reclaim — delete Windows after verify (or write the live-USB finisher)

x47-ark finish /path/to/ark-plan.conf — live-USB finish step

x47-ark status — last backup / verify state

Safety rules

  • Privileged steps use pkexec / sudo.
  • Backup-only is a first-class path — you can stop after verify.
  • Verify must be OK before reclaim.
  • EFI stays. Only the Windows boot menu entry is removed after GRUB updates.
  • Separate /home after the root partition blocks “one big partition”; Ark will say so instead of eating it.

Install / skip

Installed by modules/28-ark.sh with ntfs-3g, rsync, parted, e2fsprogs, zenity.

./install.sh --skip-ark

./install.sh --only 28-ark
